# Configuration registry

## Local ownership

Config schema1 lives in config.json beneath the companion state directory. It contains a distinct persisted clientId, explicit target (optional), paseoHome, apiOrigin (optional), allowLoopbackHttp, cloudEnabled, pinned daemonServerId, and at most16 independent per-phone pair records. Pair root keys and relay host capabilities are endpoint secrets. API target/official credentials remain private local configuration; diagnostics redact the target and home. config is atomic-replaced and flushed before activation. journal.sqlite uses WAL and synchronous=FULL. runtime.lock/runtime.json/runtime.sock are companion-only control resources; stop authenticates the local IPC request, never kills a PID supplied by a stale file.
Existing resource ownership is checked before mutation, not inferred from filenames. SQLite application_id is 0x4d524331 (MRC1), read through an immutable read-only probe before opening a writer; foreign/unmarked databases are rejected, never migrated/adopted. Unreleased development databases without that identity require a fresh temporary companion state directory, not changes to official data. Runtime locks/records carry versioned companion ownership and instance/token identity; socket cleanup requires matching provenance/inode. Atomic JSON replacement flushes file data and the POSIX parent directory before dependent tombstone cleanup.
Each pairing retains its own explicit API origin when retired, so retargeting a locally revoked installation cannot disclose its old host capability to a new operator origin. Local revokedAt is the first durable revoke time, never refreshed by retries. Retired endpoint keys remain protected until the latest of first revokedAt+24h and every durably known operation/control/attention original expiresAt+24h. A valid authenticated late post-revoke control durably advances that child high-watermark before cleanup or acknowledgement. Unsent sealed acknowledgements remain retransmittable through their child's deadline; receipt attestation/retry times never extend it. Attention ciphertext is still cleared at original expiry; only invalidation metadata survives its audit window. Cleanup durably removes revoked credentials before deleting their no-longer-needed tombstone; no old pairing is resurrected. Expired unactivated offers are pruned24h after original expiry. managedVersion is written only after exact package identity/build-file checks succeed; service installation never selects a failed/partial managed update. Roots and managed package directories carry separate ownership markers, foreign entries block purge, and official/companion data paths must not overlap.

MOREMOTE_COMPANION_HOME or --data-dir overrides platform state defaults. LOCALAPPDATA/XDG_STATE_HOME and platform homedir provide portable defaults. PASEO_HOME selects the official read-only home, PASEO_PASSWORD matches official CLI password precedence. Only paseo.pid and local-credential are read under the official home, only at an explicit connection. No credential discovery scans or official writes.

## Central limits (src/limits.ts)

Envelope request128KiB; decrypted content64KiB; send text60000 UTF-8 bytes; command/control TTL300s; enrollment/state/attention maximum600s; receipt/controlReceipt maximum8KiB serialized envelope with600s attestation interval; future clock tolerance120s (never expiry grace). User payloads expire at original TTL, minimal encrypted receipts/evidence remain24h after original operation/control expiry. Receipt revision is persisted before I/O; control ack revision1 is immutable. At most1000 operations,1000 controls and1000 attention records per pairing,100 tasks/snapshot,10 pending requests/task,16 providers,8 windows/balances/provider. Raw enhanced request limit8KiB; whole state limit60000bytes. State refresh30s, polling3s backing off to30s, HTTP timeout20s, official connection/read15s, SDK mutation timeout per pinned upstream. Capacity errors never silently evict live authority.
HTTP response limit is5MiB, separately from the128KiB request limit; the relay count-bounds command/control pages to32. This permits real bounded acquisition pages without silently truncating valid large commands.
Local pair revocation tombstones are capped at4096, never evicting live protection. Exhaustion is an explicit failure. Running cleanup removes a tombstone only after its pairing credentials have been durably removed and all immutable child audit deadlines have passed. Offline configuration-only reads cannot prune revoked keys without their journal.

## Service resources

macOS: user Library/LaunchAgents/com.moremote.companion.plist. Linux: XDG_CONFIG_HOME/systemd/user/moremote-companion.service (fallback user .config). Windows: current-user task MoRemoteCompanion and UTF-16 XML in companion state, InteractiveToken/LeastPrivilege; built-in PowerShell checks exact existing task ownership before schtasks mutation. Marker binds the data-directory hash; manager registration/file ownership mismatch fails closed. A private companion root marker refuses nonempty foreign directories and gates purge. No official Paseo service/resource is altered. Missing managers fail honestly.

## Update source

Explicit exact versions from https://registry.npmjs.org are installed with lifecycle scripts disabled into private staging, verified, then promoted to state/managed/versions/<exact-version>. Each verified version is immutable; a failed/new update cannot replace a registered executable. Only package name moremote-companion is requested; installed identity/version and built entry files must exist. Explicit service-install --yes selects the new verified version. No auto-update scheduler or official daemon upgrade. Public package availability is a release gate, not presumed infrastructure.
